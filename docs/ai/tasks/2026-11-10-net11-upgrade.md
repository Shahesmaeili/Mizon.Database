## Request and implementation

Upgrade every .NET project and provide measured .NET 10 versus 11 comparisons.
Both database projects now target net11.0; all five EF package references are
11.0.0. SDK is pinned to 11.0.100. Removed unsupported EFOptimizeContext, preserved
compiled-model generation/current-assembly copying, disabled design-time generation.

No entities, migrations, SQL business logic, stored data or database settings change.
Read-only server inspection confirmed SQL 17.0.1145.4 and Mizon compatibility170,
which supports EF11's default160. Integrated authentication remains unchanged.

Added an opt-in --benchmark JSON-path mode to the existing regression runner.
Identical source was built on SDK10/net10/EF10.0.5 before migration and on
SDK11/net11/EF11.0.0 afterwards. No extra package and no database connection is used.
The cold case covers first model/provider initialization; warm cases compare
fresh context and pooled context/set access with fixed warm-up and batches.
Results are runtime-plus-EF upgrade comparisons, not an isolated JIT-only claim.

## Validation and evidence

- SDK10 Release/x64 baseline build passed; 40 regression checks passed.
- SDK11 Release/x64 candidate build passed; 40 regression checks passed.
- SDK11 Release/win-x64 actual NativeAOT publish passed; the resulting executable
  passed all 40 regression checks without opening SQL connections.
- Existing EF NativeAOT warnings remain visible; full server AOT is not claimed.
- Timed benchmark runs and final aggregate report are coordinated sequentially by

- Local artifacts: D:/MizonTaskDiagnostics/Net11/baseline/database and
